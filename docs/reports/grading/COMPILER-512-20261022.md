# 512 MiB compilation reservation

Deployed and verified on the OTOG VM on 22 October 2026. This supersedes the
300 MiB compilation reservation, whose 256 MiB compiler limit rejected four
realistic C++ examples.

The subsequent [single compiler dispatcher](COMPILER-DISPATCHER-20261022.md)
retains this memory policy and now owns queue pickup for both concurrent job
slots. Its 33-check suite includes this report's 23 checks plus dispatcher
concurrency, recovery, shutdown and grader-main-loop checks.

Each dedicated compilation reserves exactly **512 MiB**: a **384 MiB compiler
address-space limit** plus **128 MiB scheduling padding**. The two slots together
reserve **1024 MiB**. Both durable compilation profiles use this limit. Compiler
failures produce Compile Error without a higher-memory retry. The existing
compile-time limit also returns Compile Error when exceeded.

The reservation is a scheduling allowance, not a hard cap on the entire service's
resident memory. Isolate's `--mem=393216` limits compiler process address space.
The 2304 MiB compiler-container ceiling, shared pool and fresh 1536 MiB admission
guard remain unchanged. Evaluation keeps problem memory plus its existing
256 MiB padding; direct custom-checker jobs retain their larger combined envelope.

All **23 isolated checks passed**: 20 eight-process queue races, two simultaneous
512 MiB compiler reservations, role routing, pause and memory guards, user/problem
limits, ready-program headroom, binary handoff, queue-age preservation, recovery,
single-attempt memory exhaustion producing Compile Error, old retry profiles,
custom-checker reservations, and all eight realistic C++17 programs below.

Programs use production `-O2 -std=c++17` settings and official AtCoder Library
revision `864245a00b00dd008d1abfdc239618fdb7d139da`. Unlike the earlier exploratory
384 MiB tests with 640 MiB reservations, these tests assert exactly 512 MiB in
the actual scheduler and do not override candidate memory constants. The original
exponential-template stress case reached the compile-time limit at 384 MiB, so
the final memory-specific test uses a large constant initializer and verifies a
memory diagnostic, one compilation and no higher-memory profile or leaked lease.

Deployment drained active jobs, recreated six graders and the compiler service,
restored prior grader flags and preserved saved-result fingerprints. Website
services were not restarted. All eight heartbeats, runtime source hashes in all
seven containers, no OOM/restarts, and six local/public page, ping and auth checks
passed. The later [matched architecture benchmark](DISPATCHER-BENCHMARK-20261022.md)
compares two configurations using this same 512 MiB budget. It found the single
dispatcher 16.5–24.5% slower than two persistent compiler workers in the tested
12-job bursts; all 144 comparison jobs scored 100.
