# 300 MiB compilation reservation

Previously deployed on the OTOG VM on 22 October 2026; superseded by the
[512 MiB policy](COMPILER-512-20261022.md).

Subsequent realistic compatibility testing found the 256 MiB compiler cap too
restrictive for several normal C++17 examples: PBDS ordered sets, nested STL
containers, ACL modint/convolution, and a combined ACL/PBDS contest template all
failed with `virtual memory exhausted: Cannot allocate memory`. All four compiled
and scored 100 when separately tested with a 384 MiB compiler limit. STL Dijkstra,
generic segment trees, ACL lazy segment tree, and ACL SCC/max-flow passed at
256 MiB. These eight fixtures used the production `-O2 -std=c++17` command and
official ACL revision `864245a00b00dd008d1abfdc239618fdb7d139da`. All tests used
private queue/database/sandbox state; production state and container identities
were unchanged. The policy during these tests was 300 MiB reserved / 256 MiB
compiler cap. The current policy is described in the 512 MiB report above.
Detailed test evidence is in `tmp/realistic-compiler/results.json`.

Each dedicated compilation reserves **300 MiB**: a **256 MiB Isolate compiler
address-space limit** and **44 MiB scheduling padding**. Two compiler slots
reserve **600 MiB** together, down from 1280 MiB. Both old durable compilation
profiles use this limit. Compiler failures persist Compile Error without a
higher-memory retry. Excessive template expansion can cause memory exhaustion;
ordinary syntax errors still produce their existing diagnostics. Infrastructure
errors remain Judge Error.

The reservation is an admission estimate, not a hard cap on the whole service's
resident memory. Isolate's `--mem` limits compiler process address space; the
existing 2304 MiB compiler-container ceiling remains in place. Evaluation retains
problem memory plus 256 MiB padding. Direct/custom-checker jobs retain their full
initial reservation where needed to cover checker execution; they are not
restricted to a 300 MiB combined compilation-and-evaluation envelope. Successful
compilation releases its reservation after sandbox cleanup.

Fifteen isolated checks passed, including 20 eight-process scheduling races,
real C/C++ handoff and AC results, template expansion failing with a memory
diagnostic and exactly one Compile Error attempt, no leaked artifacts or leases,
an existing retry profile using 300 MiB, and direct custom-checker reservations
safely shrinking from 1024 to 768 MiB. Tests used a disposable database.

The repeat comparison used the same 1792 MiB pool, six grader CPUs, two dedicated
compiler CPUs, three synthetic 12-job workloads, and two trials per configuration
per workload. All **144 jobs** scored 100, with no higher-memory retries.

| Workload | Shared workers, median | Dedicated 300 MiB, median | Elapsed reduction |
| --- | ---: | ---: | ---: |
| Compilation-heavy | 23.79 s | 23.10 s | 2.9% |
| Execution-heavy | 13.02 s | 12.83 s | 1.4% |
| Mixed | 18.58 s | 18.35 s | 1.2% |

These small differences support comparable throughput, not a precise universal
speedup. Execution-heavy dedicated runs reached five simultaneous evaluations,
versus four for shared workers. The minimum observed guest MemAvailable was
1593.9 MiB, above the unchanged 1536 MiB diagnostic guard. The earlier dedicated
640 MiB results are in [the original comparison](GRADER-BENCHMARK-20261022.md).

Benchmark provenance: after all 12 trials and production-state/container-identity
assertions completed, the coordinator's public HTTP lookup encountered temporary
VM DNS failure. Completed trials were retained in `300-partial.json` and collected
into `benchmark.json`. Public checks then passed from the host and, at postflight,
from the VM. Before final deployment, the coupled custom-checker reservation floor
and its preparation guard were retained and validated by the final 15-check suite.
Consequently the final source hashes differ from the benchmark candidate in those
direct-path provisions; the benchmark uses standard dedicated-stage jobs, whose
300 MiB reservations and 256 MiB compiler limits are unchanged.

Deployment drained active leases, recreated six grader containers and the compiler
container, restored previous grader flags, and preserved saved-result fingerprints.
Website services were not restarted. All eight heartbeats, deployed source hashes,
container state, and local/public page, API and authentication checks passed.
