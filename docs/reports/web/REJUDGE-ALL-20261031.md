# Password-confirmed global rejudge — 31 October 2026

`PATCH /backend/submission/problem/all/rejudge` is an explicit admin-only route. It accepts JSON `{ "password": "<current admin password>" }` and returns `{ "queued": <count> }`. The `/backend` prefix belongs to the public reverse proxy; the API route itself starts `/submission`.

The authenticated session determines the account. The service reads its current role/password hash from the database and uses the existing constant-time legacy/Scrypt password verifier. Supplying another administrator's password cannot authorize the action. Unknown body properties, empty passwords, and passwords longer than 255 characters are rejected. Incorrect passwords return 403 without invalidating the signed-in session. Password verification has a separate per-account token bucket with capacity five and one token replenished every 12 seconds, in addition to existing API limits and the shared bounded password-work queue.

All completed submissions across all problems are selected, including hidden, public, practice, and contest submissions. Existing waiting/grading submissions and submissions with active worker leases are preserved. One database transaction locks the selected submissions, clears old result trees, retry attempts, and compiled-artifact metadata, then queues them with fresh queue-entry timestamps. A current-account role/hash check is locked in the same transaction to reject a concurrent credential/role change. Worker wakeup is sent on commit. Repeating the action while those submissions remain pending does not reset their queue positions. New submissions arriving afterward proceed normally.

The endpoint does not change source code, problem/test data, submission IDs, CPU selection, worker limits, or contest priority. Contest scores follow the existing rejudge completion/recalculation behavior. Existing single-submission and numeric-problem rejudge routes remain available as before.

The admin problem page has a **ตรวจทุกโจทย์ใหม่** button. Its dialog explains the scope and asks for the current admin's password. The password field is cleared when submitting or closing, uses `type=password` and current-password autocomplete, and is kept out of React Query mutation variables/cache. The action is disabled while a request is in flight. No password is placed in a URL, local/session storage, logs, or success responses.

The additive migration `20261031020000_rejudge_all_permissions` grants the API runtime role only the additional DELETE and referenced-column SELECT privileges needed for retry/artifact cleanup. It does not grant ownership or superuser privileges. The operational retry table is provisioned by the existing grader deployment; the migration tolerates installations where that table or the named runtime role is absent.

Validation uses the actual candidate API, real JWT/session verification, and a disposable PostgreSQL database with the runtime role's real permissions. Tests cover anonymous/non-admin rejection, invalid/missing/wrong/other-admin passwords with unchanged data, valid Scrypt and legacy verification, all-problem/contest scope, result cascades, retry reset, preserved active leases and queue ages, repeated requests, password throttling, and the existing numeric-problem route. Test data and temporary credentials are removed afterward. No authenticated global rejudge is executed against production during deployment.
